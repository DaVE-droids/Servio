# Publishing Servio to the App Store and Google Play

What's already done in the code, and what only you can do (accounts,
payments, keys, and legal text). Nothing here is needed for the website —
that's `docs/DEPLOYMENT.md`.

## What you need to do

### 1. Choose the app's permanent ID — do this first

Today it is `com.example.servio`, which **Google Play rejects** and which
can never be changed after the first upload. Pick something you own, for
example `ng.edu.<institution>.servio` or `com.<yourdomain>.servio`.

Tell me the ID and I'll do the rest; it touches four things:

1. `applicationId` and `namespace` in `android/app/build.gradle.kts`
2. `PRODUCT_BUNDLE_IDENTIFIER` in the Xcode project
3. New Android and iOS apps registered in the Firebase console (the ID is
   how Firebase recognises the app), which produce a new
   `google-services.json` and `GoogleService-Info.plist`
4. `firebase_options.dart`, regenerated by `flutterfire configure`

### 2. Accounts and payments

| | Cost | Notes |
|---|---|---|
| Google Play Console | $25 once | An **organisation** account avoids the 12-testers-for-14-days rule that applies to new personal developer accounts |
| Apple Developer Program | $99/year | An Organization account needs a D-U-N-S number; an Individual account publishes under your own name |
| A Mac with Xcode | — | Required to build and upload the iOS app |

### 3. Fill in the legal pages

`web/privacy.html` and `web/terms.html` contain `[Operator name]` and
`[contact email]` placeholders. Replace them, have the institution review
the text, then deploy. Both stores check that the privacy URL works.

### 4. Create the Android upload key

```bash
keytool -genkey -v -keystore ~/servio-upload-key.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Then create `android/key.properties` (already gitignored):

```properties
storePassword=<the password you chose>
keyPassword=<the password you chose>
keyAlias=upload
storeFile=/Users/dave/servio-upload-key.jks
```

**Back the `.jks` file and its passwords up somewhere safe.** Lose them and
you can't update the app; you'd have to publish a new listing. (Turning on
Play App Signing at first upload protects against this — do it.)

### 5. Build the uploads

```bash
# Android (upload this .aab to Play)
flutter build appbundle --release --dart-define=LOCATIONIQ_ACCESS_TOKEN=<token>

# iOS (then Xcode → Product → Archive → Distribute)
flutter build ipa --release --dart-define=LOCATIONIQ_ACCESS_TOKEN=<token>
```

Bump `version:` in `pubspec.yaml` before each upload — the build number
(after the `+`) must increase every time.

### 6. Store listing content

Both stores need: a short and full description, a feature graphic (Play,
1024×500), and screenshots — phone for both, plus **iPad screenshots**
because the app currently supports iPad. (If you'd rather skip iPad, say
so and I'll restrict the app to iPhone.)

### 7. Privacy answers

Answer both forms from the same facts as `web/privacy.html` and
`PrivacyInfo.xcprivacy`: name, email, phone, photos, user content, and user
ID; all **linked to the user**, all for **app functionality**, none for
tracking or ads.

### 8. Give reviewers a way in

Reviewers must reach the whole app, so in the review notes give:

- a **student** test account,
- an **approved lecturer** test account (a fresh lecturer sign-up is stuck
  on "Awaiting approval", and a reviewer can't approve it),
- a **coordinator** test account,
- one line explaining the three roles.

Credentials are in `scripts/seed-output.json` (not in git). **Rotate the
student and lecturer test passwords first** — the old shared password is
known (it used to be in the repository; it was scrubbed from the history on
2026-09-22, but rotate anyway before handing accounts to reviewers):

```bash
cd scripts
SEED_PASSWORD='new-one' SEED_COORDINATOR_PASSWORD='another-one' node seed_test_users.js
```

### 9. Before you submit, know these

- **Push notifications aren't built.** Don't mention them in the listing.
- **Profile photos are switched off** until the Firebase plan is upgraded
  (`AppConstants.profilePhotoUploadsEnabled`).
- **Crash reporting isn't set up.** Firebase Crashlytics is free and worth
  adding before a real launch; it needs a Gradle plugin and an Xcode build
  phase.
- Apple often asks what "SIWES" means and who the app is for — answer in
  the review notes.
